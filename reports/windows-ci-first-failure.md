# Windows 首次构建失败与修复

日期：2026-11-03。运行：41584587385，提交：35bce84。

Windows runner 已实际完成 FFmpeg n7.1.5 和 whisper.cpp v1.9.5 编译；基础测试结果为 48 通过、3 失败、7 项 E2E 未执行。构建在测试阶段停止，未产生通过验收的 Windows 包。

失败原因及修复：

- 两项媒体测试使用 lavfi 合成素材，但发布配置禁用了 avdevice，因此无 lavfi 输入。改为标准库生成 PCM WAV、原始 RGB 帧经 FFmpeg 编码为 MP4；后续 E2E 同类用法同步替换。保留无音轨、损坏、空文件、中文路径与实际转码检查。
- 安全参数测试的 Python 子进程在英文 Windows 使用 cp1252 输出中文失败。测试子进程显式启用 `-X utf8`，继续检查包含中文、空格、引号、shell 符号的参数原样传递。未修改外部进程安全参数数组调用方式。
- 本地回归发现 FFmpeg 最后一帧时间戳可小于音频实际结尾；只有子进程正常退出且输出存在有效数据后，提取进度才标记完成。
- artifact 上传显式包含隐藏路径，确保 .work 中的测试记录与构建诊断能被保留。

补充实际中文语音 MP4 → 单声道 16 kHz WAV 集成测试。修复后 Linux 本地回归：52 passed，7 deselected，2.78 秒；ruff 通过。此结果不代表 Windows 重建或识别 E2E 已通过；以重新运行的 Windows CI 为准。
